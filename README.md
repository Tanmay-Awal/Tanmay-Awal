<summary><b>🔷 Ocean-IQ — Natural Language Oceanographic Intelligence Platform</b></summary>

<br/>

A full-stack AI platform that makes 10+ years of global ARGO float sensor data accessible through natural language queries — combining semantic search, geospatial retrieval, and real-time LLM synthesis with interactive 3D data visualisation.

| Attribute | Detail |
|:---|:---|
| **Stack** | Next.js · Flask · PostgreSQL · ChromaDB · RAG · Plotly |
| **Scale** | 10+ years of global ARGO oceanographic sensor data |
| **Pipeline** | 8-step Intelligence Engine: intent → geocoding → semantic search → retrieval → analytics → chart generation → LLM synthesis |
| **Streaming** | SSE-based real-time streaming for progressive response rendering |
| **Visualisation** | 5 interactive Plotly chart types + 3D interactive globe |
| **Deployment** | Vercel + Render · Neon serverless PostgreSQL |
| **Repository** | [![GitHub](https://img.shields.io/badge/View%20Repo-6D28D9?style=flat-square&logo=github&logoColor=white)](https://github.com/tanmayawal/ocean-iq) [![Live](https://img.shields.io/badge/Live%20Demo-7C3AED?style=flat-square&logo=vercel&logoColor=white)](https://ocean-iq.vercel.app) |

Architected the RAG pipeline using Gemini text embeddings stored in ChromaDB, enabling semantic search across float metadata. The 8-step Intelligence Engine handles the full query lifecycle — from geospatial intent classification to structured Plotly chart generation — streamed progressively to the frontend via SSE.

<br/>
</details>

<details>
<summary><b>🔷 CyberWatch — Automated Threat Intelligence for 100+ Daily CVEs</b></summary>

<br/>

A self-hosted, zero-cost threat intelligence automation system ingesting 100+ CVEs daily from four live feeds, enriching and correlating them through a five-agent n8n pipeline, and dispatching prioritised Telegram alerts — with zero human intervention.

| Attribute | Detail |
|:---|:---|
| **Stack** | n8n · Neo4j · Qdrant · PostgreSQL · Groq · Gemini |
| **Scale** | 100+ CVEs processed daily |
| **Agents** | 5 specialised agents: Collector · Enricher · Correlator · Prioritizer · Dispatcher |
| **Sources** | NVD · CISA KEV · AlienVault OTX · OSV.dev |
| **Databases** | PostgreSQL (structured) · Qdrant (vector) · Neo4j (graph — CVE-to-threat-actor) |
| **Inference** | Groq Llama 3.1 — sub-second CVE classification |
| **Deployment** | Fully self-hosted via Docker Compose · Zero cost |
| **Repository** | [![GitHub](https://img.shields.io/badge/View%20Repo-6D28D9?style=flat-square&logo=github&logoColor=white)](https://github.com/tanmayawal/cyberwatch) |

Designed a three-database architecture that separates structured CVE storage (PostgreSQL), semantic similarity search (Qdrant), and relationship mapping between CVEs and threat actors (Neo4j). The Groq-powered Llama 3.1 classification step achieves sub-second throughput, enabling the entire daily pipeline to run autonomously without cloud costs.
